# 完了報告: 画面構成の整理(タブ分割)

対象: AI記録支援(本番PoC) — `poc-app/`
実施日: 2026-09-17 〜 2026-09-18
関連: `docs/change-log.md` CHANGE-017〜021

## 背景・目的

これまで1ページに「職員の入力・AIアウトプット・保存した記録・モニタリング」の4セクションが縦に並んでおり、施設長へのデモで見せる際にスクロールが多く、何ができるツールか伝わりにくいという課題があった。

**目的**: 機能ごとに画面を分け、初めて見る人でも今どの作業をしているか迷わない構成にする。新機能の追加・既存機能の振る舞い変更・DBスキーマ変更は行わず、構成と見た目の整理に限定する。

## 実施内容

### 1. 画面をタブに分割(CHANGE-017)

「書く」「見る」「モニタリング」「管理」の4タブに再構成した。

| タブ | 内容 |
|---|---|
| 書く | 職員の入力(仮名運用の注意書きを維持)→AI分類→6項目編集・保存・印刷 |
| 見る | 保存済み記録の一覧・検索 +(新規)選択した記録をその場で読み取り専用プレビュー表示し、印刷/PDF出力 |
| モニタリング | 個別支援計画モニタリング下書き生成(「下書きです」「モニタリング結果報告書とは別物」の注記を維持) |
| 管理(新設) | 児童マスタ登録・施設スタッフ招待を集約 |

非アクティブなタブは条件付きレンダリングで消さず、`hidden`属性で常時マウントしたまま非表示にする方式にした。6項目・モニタリング5項目の入力欄が`contentEditable`(React state化されていない)ため、アンマウントすると未保存の編集内容が失われるのを避けるための設計。

### 2. 印刷/PDF出力の見直し(CHANGE-017, 020)

非アクティブタブが常に非表示になる性質を利用し、旧来の`printTarget` state・`data-print-target`属性による切り替え機構を廃止。画面に見えているタブの内容だけが自然に印刷される設計に変更した(`printNow()`に統合)。

途中、ヘッダー固定化(下記4)の副作用でsticky要素が効かなくなる不具合が発生し、原因(`overflow-x: hidden`がposition:stickyを無効化する既存グローバルCSSとの相互作用)を特定して`overflow-x: clip`に修正した(CHANGE-020)。

### 3. 見るタブの見た目整理(CHANGE-018, 019, 021)

- プレビューを一覧の下ではなく右側(2カラム)に配置し、選ぶたびに常に同じ場所に出るようにした
- 一覧の行自体をクリック可能にし、独立していた「プレビュー」ボタンを廃止(ボタン数を削減)
- 「削除」は控えめな色にして「編集する」と視覚的に区別し、誤クリックを防止
- 絞り込みUIを「児童」「期間」の2段に分け、狭い画面での折り返しを整理
- 「保存先はSupabase…」という技術的な説明文を「同じ施設のスタッフ全員が見られる一覧です」に簡潔化

### 4. ヘッダー+タブバーの固定(CHANGE-019)

`position: sticky`でmasthead+タブバーをまとめ、スクロールしても常にどのタブかが分かるようにした。

## デモでの推奨動線

1. **「書く」で軽く**: サンプル文を挿入→AI分類分け→6項目に振り分かる様子と、その場で直接編集できることを見せる。
2. **「モニタリング」が本命**: 事前に同じ児童で複数件の記録を投入しておき、支援目標を入力→下書き生成。半年分の記録を読み返してモニタリング下書きを作る児発管の負担を、蓄積データから直接解消する場面なので、ここに一番時間を割く。
3. **「見る」で補足**: 蓄積された記録一覧とプレビュー印刷を軽く見せ、紙の記録として出せることを示す。
4. **「管理」は最後に一言だけ**: 児童登録・スタッフ招待はここ、と触れる程度で十分。

## 今後の検討事項

- モバイル幅でのsticky/レイアウトは今回のデモ想定(PC画面)を優先して簡易確認のみ行った。実運用でスマートフォン等からの利用が想定される場合は、改めて狭幅での確認が必要。
- 保存済み記録のプレビューには、機械チェック(ヒヤリハット転記漏れ警告)・AIの自信度が低い文(`uncertainNotes`)は表示されない(保存データに含まれないため)。仕様として明示済みだが、運用上気になる場合は別途検討。
